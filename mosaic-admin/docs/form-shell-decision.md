# 表单 / 详情页：整页壳，不是抽屉（2026-11-18 决策）

> 背景：旧仓「进口订单 新增/修改」表单 `enter-form.vue` **1817 行 / 47 个 `base-form-item`、
> 内含 2 个子表（`base-edit-table`，15 处引用）+ 配送/收货/附件等 11 处子列表组件**。
> 之前探针把「表单第 1 节」塞进 34rem 的抽屉里，是跟着旧仓「弹窗表单」的惯性走；
> 抽屉装不下带子表、多字段的表单，继续加宽只会变成「不像抽屉也不像页面」。
> 本决策把**表单壳改成整页（常驻标签页）**，抽屉只留给「详情 / 选择器 / 确认」。

## 〇、详情页也一样（2026-11-18 补）

旧仓「进口订单详情」是 `details.vue` —— **1628 行 / 56 个只读 `base-form-item` / 多个折叠区**
（要点 / 成交与费用 / 报关 / 包装 / 收发货人…）+ 明细 + 审批时间轴，本来就是**路由整页**，不是抽屉。
我们先前做的 `order-detail-drawer` 只是切片验证用；接真实内容后同样装不下，因此：

- **委托单详情 → 整页**（`pages/import-order/detail.html` + `components/order-detail.html`）：
  要点 + 贸易/报关 + 明细子表 + 审批时间轴，顶部「返回 / 编辑」；
- 列表点行直接进详情整页；详情页「编辑」进整页表单；
- **抽屉只留轻量场景**：用户详情（8 字段 + 角色 chips）、子表行表单、选择器。

## 一、结论

| 形态                                                                       | 用在哪                                          | 理由                                                        |
| -------------------------------------------------------------------------- | ----------------------------------------------- | ----------------------------------------------------------- |
| **整页表单**（`pages/<域>/<页>/edit.html`，hidden 路由，常驻 o-page 标签） | 新增 / 修改（字段多、带子表、需要保存前脏检查） | 宽度给两栏字段 + 任意宽子表；可滚动长内容；保存动作常驻可见 |
| **抽屉**（`mc-drawer`）                                                    | 详情、子表行的「添加/编辑」轻表单、选择器       | 从列表上下文弹出、不打断列表状态；内容短                    |
| **对话框**（`mc-dialog`）                                                  | 确认、审批意见、单字段输入                      | 必须立刻决策的短交互                                        |

**判定规则**：表单 / 详情里出现「子表 / 多段 / 保存前校验汇总 / 宽度 > 40rem」任意一条 → 整页。
纯 3–5 字段的轻量编辑、只读轻量详情（如用户卡片）才用抽屉。

## 二、页面解剖（`components/order-edit.html`）

```text
┌─ 顶栏（sticky）：← 返回列表 · 标题 + 单号/客户 · 状态/保存提示 · [取消] [保存] ─┐
│                                                              │
│  ① 基本信息（两栏字段网格）                                    │
│     mc-form + mc-form-item；只读字段 readonly                    │
│  ② 订单明细（子表，占满宽）                                     │
│     行数 + 操作；mc-data-grid（v0 只读 + 行删除）                │
│  ③ 配送信息（两个子表：提货/送货）                               │
│     mc-data-grid × 2（空态可见）                                │
│                                                              │
└─ 底部动作条：状态文案 + [取消] [保存]（与顶栏同一套动作）──────────┘
```

- **路由**：`#/pages/import-order/edit.html?id=<orderId>`；shell 的 `routeFile()` 只取文件段匹配注册表，
  页面自己解析 `?id=`（页面仍是 hidden 页，不进菜单）。
- **状态**：页面自身持有`_detail`（主表原值）+ `_lines`（明细数组）+ `_take` / `_send`；
  mc-form 不持数据（见 `packages/form/api.md`），提交时 `getValue()` 合并回 `_detail`。
- **脏检查（下一步）**：进入时快照 + 离开/关闭标签前比对；有改动弹 `mc-dialog` 确认。
  标签关闭逻辑在外壳：需要 shell 暴露「注册离开守卫」的钩子（未做，列入下一步）。
- **保存**：`POST /api/orderImport/update`，payload = 主表 + `orderImportDetailDTOList`（明细带 id）+
  `orderDeliveryTakeDTOList` / `orderDeliverySendDTOList`（后端要求非 null）。
  成功后派发 `window` 事件 `admin-data-changed`（detail.module = 'import-order'），列表页据此刷新。
- **取消/返回**：`location.hash = '#/pages/import-order/list.html'`（列表是常驻标签，状态仍在）。

## 三、子表怎么做（当前缺口，先诚实标注）

v0：子表**只读 + 行删除**；「添加明细」按钮禁用（`title="待可编辑网格"`），避免造出无法编辑的空行。
**下一件库侧的事：`mc-data-grid` 的可编辑模式**——契约草案：

| 能力         | 写法（草案）                                                                                 |
| ------------ | -------------------------------------------------------------------------------------------- |
| 列声明可编辑 | column `{ key, title, editable: true, editor: 'input' \| 'select' \| 'number' }`             |
| 受控数据     | 行对象在业务侧，grid 只发 `cell-change`（`{ rowKey, key, value, row }`），不改传入行         |
| 提交时机     | 单元格 blur / Enter 发事件；Esc 还原；行级校验结果由业务侧写回行 `errors`（v0 不做内置规则） |
| 行操作       | 行 `data-action`（已有）+ 行的增删由业务侧数组驱动（`setRows`）                              |

不做的：公式、合并单元格、跨行粘贴、单元格级权限 —— 等真实需求。

## 四、对「不跟旧仓走」的取舍

- 旧仓表单是 **47 项全塞一屏 + 弹窗**；我们不复制它的字段分组，按「基本信息 / 明细 / 配送」重新分节，
  字段顺序按使用频率，只读/可编辑混排有明确视觉区分。
- 旧仓「明细表格」是 vxe-table 的可编辑表格（列宽、校验、批量粘贴都耦合在页面里）；
  我们抽成「mc-data-grid 可编辑模式 + 业务 columns」，页面不碰 cell DOM。
- 旧仓「新增/修改/复制」是同一个组件按 type 分支；我们先做修改（id 存在），新增等 create payload
  （含默认值 / 单号生成规则）确认后再接，避免猜业务默认值。

## 五、详情页 / 表单页路由

- 都是 hidden 页（不进菜单）：
  - `#/pages/import-order/detail.html?id=<id>`
  - `#/pages/import-order/edit.html?id=<id>`
- shell 的 `routeFile()` 只取 hash 的文件段匹配注册表，页面自己解析查询串；
- 详情页只读：同一 id 已加载就保留（切标签回来不重拉网络）；换 id 重新拉；
- 列表 ↔ 详情 ↔ 编辑 之间用 hash 跳转，列表是常驻标签，回到列表不丢状态。

## 六、详情页的关联 Tab（菜单驱动 + 懒挂载）

### 旧仓怎么做的（实测）

Tab 不写死在页面里：`createTabsOpitonsByMenuId(route.meta.id)` 调
`GET /admin/menu?type=3&parentId=…` 拿「页签」类型菜单节点，每个节点带
`name / permission / componentPath`；再按 componentPath 动态 `require('@/views'+path)`
把**别的模块的页面组件**挂进当前详情（传 `detailsMark:true` + 行数据）。

实测这套配置（开发租户）：

| 层级                 | 菜单 id              | 数量   | 内容                                                                                                         |
| -------------------- | -------------------- | ------ | ------------------------------------------------------------------------------------------------------------ |
| 一级（详情页外层）   | `102532`（中国进口） | **11** | 详情 / 入库计划 / 收货异常记录 / 入库单 / 进口预报 / 报关单 / 出库计划 / 出库单 / 库存记录 / 附件 / 操作日志 |
| 二级（详情节点内部） | `102538`（详情）     | **8**  | 订单详情 / 付款通知书 / 应收结算单 / 应收费目 / 应付费目 / 汇差记录 / 开票申请 / 税单                        |

所以「详情页」本质是**两层 Tab 容器**：外层挂别的模块的关联列表，内层挂详情自己的分面；
不是我们之前那种「一页竖排四个 section」。

### Mosaic 怎么展示

- **数据流保持旧仓同构**：Tab 仍来自菜单接口（label / 权限 / 模块归属运维可配），
  `shared/api/menu.js#getUserTabs(parentId)`；`shared/modules/import-order/detail-tabs.js`
  只放「旧 componentPath → Mosaic 本地组件」的映射表，**没映射到的落 placeholder**，不假装已实现。
- **外层**：`components/order-detail.html` = 动作条 + `mc-tabs`（`no-panel` 只当标签条）+ 自有内容容器。
- **内层**：外层「详情」Tab 渲染 `components/order-tab-details.html` —— 再一套 `mc-tabs`，
  第一个子页签「订单详情」渲染 `order-tab-summary`（原四节内容）。
- **懒挂载 + 常驻**：Tab 面板内容**不在初始时创建**；第一次激活才 `document.createElement` + 调
  `load(orderId)`，之后只切显隐（keep-alive），切回不重复请求。
- **权限过滤**：用菜单节点的 `permission`（真实权限码）走 `can()` 过滤；没权限的 Tab 不渲染。
- **深链**：`#/pages/import-order/detail.html?id=…&tab=<菜单id>`；点 Tab 用
  `history.replaceState` 更新，刷新 / 分享都能直达同一页签。
- **URL 里的 tab 值是菜单 id**（不是中文名），重命名 Tab 不破坏旧链接。

当前已接真实组件的 Tab（其余为 placeholder，界面上明确写「旧组件路径 + 待接入」）：

| Tab              | 旧 componentPath                           | Mosaic 组件         | 数据来源                                                  |
| ---------------- | ------------------------------------------ | ------------------- | --------------------------------------------------------- |
| 详情（二级容器） | `/business/order/import-order/details`     | `order-tab-details` | 菜单 102538                                               |
| 订单详情（二级） | `…/details-tabs/views/order-details/index` | `order-tab-summary` | get / detail page / auditList                             |
| 附件             | `/common/annex`                            | `order-tab-annex`   | `/admin/sys-file/page`（fileModule=进口订单，bizId=单号） |
| 操作日志         | `/common/opr-records`                      | `order-tab-opr`     | `/admin/operateLog/page`（type=order_import）             |

### 刻意不做 / 下一步

- **不做「一个旧组件一个 iframe」**：iframe 会丢主题、丢权限上下文、还多一次页面启动；
  映射表逐个本地化，没接的明确占位。
- Tab 上的**数量角标**（如「附件 3」）：要额外 count 接口，等真需求；
- 「在新标签打开该关联模块」：先不做，等对应模块页进 Mosaic；
- 菜单 id 目前写在 `detail-tabs.js`（`102532/102538`），下一步可做成「按当前模块路径查菜单」，
  避免换租户后 id 变化。

## 七、脏状态与取消语义（本次实测后补）

表单在**常驻标签页**里，所以「改了一半切走再回来」不能丢：

| 动作                       | 行为                                                                               |
| -------------------------- | ---------------------------------------------------------------------------------- |
| 编辑中切到别的标签再回来   | 保留本地改动（页面实例不销毁；页面 `resync()` 发现 `editor.isDirty()` 就不重新拉） |
| 点「取消」/「← 返回列表」  | 丢弃本地改动（清脏标记）；再进同一单会重新从服务端拉                               |
| 点「保存」成功             | 清脏标记；派发 `admin-data-changed`，列表页刷新                                    |
| 用 `?id=` 打开**另一张单** | 直接换数据（旧单未保存改动丢弃——下一步补「离开确认」对话框）                       |

已知限制（记下来，别假装没有）：

- 标签身份仍是**按文件**（`edit.html` 一个 tab），不是「每张单一个 tab」；多单并行编辑要等 shell 支持
  「tab key = file + query」。
- 浏览器刷新 / 关标签会丢未保存改动（没做草稿持久化）。
