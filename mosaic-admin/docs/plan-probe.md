# 共建方案 v4：先做"探针"，再谈发布与签出

> 前提更新（2026-11-16）：
> ① 新仓库（`mosaic-admin`）**不是 1:1 复刻**，只做功能子集，允许有意优化；
> ② 旧仓继续演进，**不追平**，只取一次性快照；
> ③ `mosaic-admin` 走上正轨之后 Mosaic UI 才正式发布，之后把 admin 签出成独立仓库；
> ④ **新工程真正的任务有两个**：把 Mosaic 的组件做成"别人敢用"的库；以及搞清楚 Web Components
> 在 20 万行 / 800 页量级的 ERP 里到底行不行 —— **不行就放弃这条路**。

相关：[可行性评估](./assessment-rewrite.md)

---

## 0. 先把"成功"定义成可判定的问题

这次投入的产出不是"一个能上线的 ERP"，而是**三个答案**：

| #   | 问题                                     | 判定依据                                             |
| --- | ---------------------------------------- | ---------------------------------------------------- |
| 1   | **WC + ofa + 免构建 撑不撑得住大项目？** | 性能/内存/请求数/调试成本/协作成本五项指标（§4）     |
| 2   | **Mosaic 能不能被做成"敢发布"的库？**    | 探针中真实使用的组件，契约稳定性与硬化程度（§7、§8） |
| 3   | **换栈后页面吞吐是变快还是变慢？**       | 每类页面的"人日/页"，与旧栈（Vue2）对照              |

**"放弃"是合法结果**，但必须"便宜地放弃"：总预算上限 **2 人 × 10 周 ≈ 5 人月**，
且失败也要留下可复用资产（组件、令牌、性能基线、一份决策报告）。

├─ docs/  tests/  tools/

## 2. 探针范围：8 个切片（不是 833 页）

每个切片都对应一类"大规模才会暴露"的风险，选错了探针就白做：

| #   | 切片                                                                                                            | 它代表的风险                                                   | 验收标准                                      |
| --- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------- |
| 1   | **外壳**：多级菜单、多标签页、主题切换、按钮级权限、全局搜索                                                    | 路由/状态/缓存/主题在没有响应式框架时怎么组织                  | 同时开 10 个标签，切换不丢状态、不卡顿        |
| 2   | **简单列表**（risk 模块，50 行、3 个搜索项）                                                                    | 吞吐基线（不该被这一项拖累）                                   | 从零到跑通真实接口 ≤ 2 人日                   |
| 3   | **重列表**（import-order 列表：500 行、单元格含按钮/标签/金额、复选批量、合并单元格、展开行、固定表头、列设置） | **mc-grid 的全部难点 + 内存/帧率**                             | 首屏 ≤ 1.2s、滚动 ≥ 50fps、选中/批量/展开可用 |
| 4   | **最重表单**（enter-form 1,818 行拆成 4 个 section）                                                            | **模板表达力**：联动、字典、金额精度、日期范围、自动完成、上传 | 不出现"大面积手写 DOM"（§5 指标 1）           |
| 5   | **详情抽屉**（主从表 + 审计时间轴 + 附件 + 嵌套抽屉）                                                           | 浮层/嵌套/滚动/焦点管理                                        | 嵌套 3 层不跑位置、Esc/焦点正确               |
| 6   | **导入流程**（上传 → 校验 → 错误报告下载 → 重试）                                                               | upload + 长任务 + 文件下载 + 进度反馈                          | 10 万行文件的失败与重试路径可用               |
| 7   | **看板**（echarts UMD + 自适应）                                                                                | 无构建引入第三方 + 容器尺寸变化                                | 窗口缩放不糊、无布局抖动                      |
| 8   | **iframe 报表页**                                                                                               | 与旧系统混排、token 透传、路由参数                             | 内嵌页能带参、能回跳                          |

**明确不做**：订单/财务全流程、打印、导入导出全量模板、权限矩阵管理、800 页批量迁移。
探针的目标是"照 X 光"，不是"盖完楼"。

## 4. 度量：每项都要有测法与目标值

| 维度   | 指标                                                            | 怎么测                                                                | 目标（内网、Chrome 最新）                                |
| ------ | --------------------------------------------------------------- | --------------------------------------------------------------------- | -------------------------------------------------------- |
| 吞吐   | 人日/页：简单列表 / 重列表 / 表单节 / 详情抽屉                  | 从拿到旧代码到跑通真实接口                                            | ≤ 2 / ≤ 4 / ≤ 1.5 / ≤ 2；**第 2 个同类页面下降 ≥ 40%**   |
| 性能   | 500 行网格首屏；滚动帧率                                        | Performance 面板（冷/热各 3 次取中位）                                | ≤ 1.2s；帧率 ≥ 50fps                                     |
| 性能   | 表单节打开到可交互                                              | 同上                                                                  | ≤ 1s（每节）                                             |
| 内存   | 同时开 10 个标签，来回切 10 次                                  | DevTools Memory 快照对比                                              | 峰值 ≤ 400MB；切换后增长 ≤ 10%，无单调上升               |
| 网络   | 进入模块的请求数与字节数                                        | Network（禁用缓存 / 命中缓存各一次）                                  | 冷 ≤ 8 请求、≤ 300KB；热 ≤ 2 请求                        |
| 稳定   | 运行时错误数                                                    | console 错误计数（每切片）                                            | ≤ 1/页，且无框架级错误                                   |
| 可维护 | 页面行数；改一个字段平均动几个文件；`proto` 里 DOM 操作行数占比 | 脚本统计 `querySelector/addEventListener/innerHTML` 行数 / 页面总行数 | 页面 ≤ 120 行；字段改动 ≤ 2 文件；**DOM 操作占比 ≤ 25%** |
| 兼容   | 企微内置浏览器 + 客户现场 Chrome 版本：浮层、表格、上传         | 真机逐项点                                                            | 全绿；不可用则必须有降级方案                             |
| 上手   | 没用过 ofa 的同事改一个页面所需时间                             | 观察 1 人 1 天                                                        | ≤ 4 小时能改一个字段                                     |
| 契约   | 组件 `api.md` 变更次数/周                                       | git log 统计                                                          | 第 6 周后 ≤ 1/周                                         |

**关键指标只有两个**（其余是守卫）：**每类页面的人日**、**10 标签下的内存与帧率**。
如果这两项不比旧栈好，换栈就没有意义。

## 5. 已知会翻车的 9 个点（探针就是去撞它们）

| #   | 机制                                                                                             | 在探针里怎么观察                                                          | 撞了怎么办                                                         |
| --- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------ |
| 1   | **模板表达力不足 → 命令式 DOM 化**：没有作用域插槽/computed，复杂联动会退化成 `proto` 里手写 DOM | 统计 `proto` 中 `querySelector/addEventListener/innerHTML` 行数占页面比例 | ≤25% 可接受；>40% 说明模板不够用，要么补 `computed` 语义，要么放弃 |
| 2   | **shadow DOM 实例成本**：每组件一份 shadow root + 样式表，多标签时叠加                           | 10 标签内存与帧率；`adoptedStyleSheets` 是否共享                          | 共享样式表 + 减少嵌套层数；仍不可接受则判定红线                    |
| 3   | 无构建：请求数、无 tree-shaking、缓存全看服务器                                                  | 冷/热网络数据                                                             | 页面内合并组件引入；关键组件预取                                   |
| 4   | 无 lint/类型：`.html` 里的脚本查不到                                                             | 探针期 bug 分类统计（低级错误占比）                                       | `tsc --checkJs` 覆盖 JS；页面脚本抽检脚本；模板用固定骨架          |
| 5   | 生态断层：Vue 组件全不可用                                                                       | 看板/富文本/编辑器/导入向导                                               | UMD 副本；实在没有再写组件                                         |
| 6   | 路由与缓存：没有 keep-alive 等价物                                                               | 标签页切换保状态                                                          | 自建状态快照；成本过高即是红线                                     |
| 7   | 调试：Shadow DOM 断点、事件重定向、模板运行时错误栈                                              | 记录"一个 bug 平均定位时间"                                               | >2h/个 即判定红线                                                  |
| 8   | 表单语义：没有原生 `<form>`，自动填充/密码管理器/a11y 都要自建                                   | 用 1Password/浏览器自动填充试登录与表单                                   | 自建桥接（隐藏原生 input）或接受损失                               |
| 9   | 打印/水印/埋点：隔离的 shadow 让全局注入变难                                                     | 试水印覆盖与打印预览                                                      | 用 `::part` + 宿主级覆盖；不行则记录为已知限制                     |

## 6. 判定规则（三条出路，必须提前写好）

**继续（换栈）**：① 两个关键指标（人日、10 标签性能）不劣于旧栈且至少一项明显更好；
② §4 其余指标无红项；③ 组件契约连续 2 周稳定。

**收敛（缩小 WC 的使用面）**：性能或表达力在复杂页面上不过关，但简单的展示/配置页明显更快 →
ERP 主系统走 Vue 3 迁移，WC 只用于"内部工具 + 独立小应用"。这条路要保留 Mosaic 的组件成果。

**放弃**：以下**任两条**成立：

1. 10 标签内存 > 600MB 或帧率 < 30fps，且共享样式表/降层后无改善；
2. 复杂表单 DOM 操作占比 > 40%，且补不出模板层能力；
3. 企微/客户浏览器上浮层不可用且无降级；
4. "一个 bug 平均定位 > 2 小时"或新人 1 天改不动一个字段；
5. 组件契约连续 3 周变更 ≥ 5 次/周（说明 API 远未定型，发布无望）。

**放弃时保留什么**（务必写进结论报告）：

- `mc-grid` / `mc-upload` / `mc-autocomplete` / `mc-drawer` 等已完成组件（仍是自定义元素，Vue 3 项目可直接嵌）；
- 令牌与主题（可作为设计语言沉淀）；
- 性能/内存/请求数基线数据；
- "WC 在 20 万行 ERP 里哪几件事不行"的具体清单（这本身就是最有价值的产出）。

## 7. 好组件的定义（探针的"组件产出"验收）

每个在探针里用到的组件，每周都要过一遍这份清单（不是最后补）：

1. **键盘可达**：Tab 顺序、Esc、方向键、焦点归还；
2. **四种状态**：空 / 加载 / 错误 / 禁用；
3. **受控与非受控**都能用（`default-*` 与 property 两条通道）；
4. **暗色**只靠令牌换值，组件里不写 `dark:`；
5. **规模**：500 项列表 / 200 个选项不卡；
6. **事件语义**：`change` 与 `input` 区分清楚、载荷带 `data`；
7. **`api.md` + demo + 冒烟套件**齐备，`pnpm check` 绿；
8. **零业务词**（没有 `permission/orderNo/apiPrefix`）；
9. **`CHANGELOG`** 记录契约变更。

## 8. Mosaic UI 的"发布就绪"标准（发版被 admin 就绪度 gate 住，得量化）

- ≥ 6 个组件在探针中被真实使用，且**连续 4 周零 breaking change**；
- `api.md` 变更 ≤ 1 次/周；
- 每个发布组件：冒烟套件 + 文档页 + §7 清单全绿；
- **外部消费者验证**：在仓库之外新建空目录，只按文档里的 CDN/相对路径引入方式跑通（不能依赖仓库内相对路径）；
- 打 `0.1.0` tag 后，按 README 里的 jsDelivr URL 实际能 200、能渲染。

> 换句话说：**发布不是"admin 做完了"，而是"库的契约稳定 + 外部能独立消费"**。

## 9. 规则与工具（沿用 v3，摘要）

**八条硬规则**：① 应用只经 `./vendor/mosaic/<slug>/<slug>.html` 引用库；② 库不 import `mosaic-admin/`；
③ 页面 ≤ 120 行、不写业务计算/不直接 fetch；④ 新组件进库前应用里 ≥ 2 个调用点；
⑤ 契约变更同提交更新 `api.md` + `CHANGELOG` + 页面；⑥ `vendor/mosaic` 永不手改；
⑦ `vendor/lib/` 只放 UMD 并记版本；⑧ 生成物（页面注册表）可重生成、缺失即失败。

**工具四处**：`tsconfig.json` include `mosaic-admin`（排除 vendor）；`package.json` 加 `dev:admin` / `check:app`；
`tools/serve.mjs` 不改（`/mosaic-admin/` 天然可达）；prettier/markdownlint 纳入 `mosaic-admin`。

**签出清单**（放附录，10 周后不一定走到，但先写好）：
`git subtree split -P mosaic-admin -b admin-split` → 新仓库 → vendor 换真实副本 → 新仓库脱离 mosaic 单起 → 打 `0.1.0`。

## 10. 风险与对策

| 风险                                 | 对策                                                 |
| ------------------------------------ | ---------------------------------------------------- |
| 探针变成"又做一个 ERP"（范围失控）   | 切片清单写死；新增切片必须换掉一个；10 周硬截止      |
| 为了性能指标做特调，结论失真         | 所有页面用真实接口与真实数据量（500 行/1.8k 行表单） |
| 组件为探针临时妥协，污染库           | 硬化清单每周跑；业务形状一律进 `components/`         |
| 旧仓继续演进导致心理压力（追平冲动） | 明确"不追平"，只在收敛/切换前做一次对账              |
| 放弃被当成失败                       | 开工就把 §6 判定规则与"保留资产"写进项目文档         |
| 一个人做，结论主观                   | 关键指标用脚本测（内存/帧率/请求数），不靠体感       |

## 11. 需要你定的 3 件事

1. **10 周 / 2 人**这个预算能接受吗？（可以缩成 6 周 / 1 人，但去掉看板、iframe、导入三个切片）
2. **探针模块**定为 `risk`（简单列表）+ `import-order`（重列表 + 最重表单）吗？
