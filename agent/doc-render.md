## 二、页面结构（改后）

```html
<doc-crumb></doc-crumb>
<h1>Button <code>mc-button</code></h1>

<mc-alert class="doc-notes" color="warning" icon heading="注意事项">

  </ul>
</mc-alert>

<h2>例子</h2>
… 每个演示：标题 →（可选）说明 → 组件 → 代码 …

<!-- 参考区：由 md 渲染，四节 -->
<doc-spec src="./api.md"></doc-spec>

<doc-pager></doc-pager>
```

| 顺序 | 块                                   | 来源                        |
| ---- | ------------------------------------ | --------------------------- |
| 1    | `<doc-crumb>` + `<h1>` + `.doc-lead` | 手写                        |
| 2    | **注意事项（`<mc-alert>`）**         | 手写（**上移**，本次改动）  |
| 3    | `例子`                               | 手写 + `demos/*.html`       |
| 4    | `属性` / `事件` / `插槽与 part`      | **由 md 渲染**（本次改动）  |
| 5    | `<doc-pager>`                        | 手写                        |

⚠️ **每页要自己注册 `mc-alert`**：站点外壳（`docs/layout.html:285-305`）只注册了
code / icon / collapse(-item) / menu(-item) / breadcrumb(-item) / card，**不含 `mc-alert`**。
漏了的话 ofa 的 `*:not(:defined){display:none}` 会把整条提示连内容一起藏掉 —— 不报错，
且**同一个页面两种表现**：从首页点进来正常，深链打开再刷新就空白（[P44](../pitfalls/05-pages.md)）。
写法照 [`doc-pages.md`](./doc-pages.md) §二 的既有约定，正文最前面加一行：

```html
<l-m src="../alert/alert.html"></l-m>
```

（`mc-alert` 内部有 `await load('../icon/icon.html')`，会连带取一次 icon，不用单独注册 icon。）

**样式**：`docs/content.css` 要加 `.doc-notes` 两条 —— 列表的上下间距，以及
`--mc-alert-body-color` 改回正文色（`part="body"` 默认是 `fg-muted`，注意事项不该是次要信息）。

## 三、md 里只写四节

以 `mc-button` 为例：

````md
# mc-button ← h1 + 引用块 + 第一个 ---：agent 开场白区，不渲染

> 共用约定见 [api/README.md](./README.md) · 源码 `packages/button/button.html` · M1 · 已实现

```html ← 简短用法片段，agent 检索用（页面有活的 demos）
<mc-button color="danger" variant="outline">删除</mc-button>
```

## 属性 ← 以下 = 渲染进参考区的公开区

| 名称 | 值 | 默认 | 说明 |

## 事件

| 名称 | 类型 | 说明 |

## 插槽与 part

| 名称 | 说明 |
````

> **2026-09-28 再改：`agent-only` 区清空了。** 原来堆在它下面的「令牌 / 实现约束 / 刻意不做的 /
> 为什么不发事件」全部搬进单元 `README.md`（那份**不发给使用者**，放得下这些）。
> api.md 现在瘦成**纯渲染源**：开场白 + 七节，没有第二个隐藏区 —— 也就没有「写了但不渲染」的错觉。
> 令牌的对账跟着搬走了：新增 `unit-tokens` 面（`packages/{slug}/README.md` 的令牌表 ↔ 组件代码）。

**三条边界规则**：

1. 第一个 `---` 之上**不渲染**（agent 开场白 + 用法片段）；
2. `<!-- agent-only -->` 之下**不渲染**（规则还在，但现在没有 md 用它了；留着是给将来再分层的余地）；
3. 中间只有**白名单七节**渲染 —— `属性` / `方法` / `事件` / `配置` / `插槽与 part` / `插槽` / `part`。
   **其余节名一律不渲染**（令牌、`实现约束`、`刻意不做的` 都在白名单外 —— 它们现在住在 README）。
   白名单是硬的：将来加新节不会误渲染出去，反过来缺节会红（见 §六 守卫）。
   `方法` / `配置` 是给命令式组件留的（`message()` 的参考区就是这两节）。

**多标签组件**：`## 属性` 下挂 `### mc-collapse` / `### mc-collapse-item` —— 与页面现有的
`<h2>属性</h2>` + `<h3>mc-collapse</h3>` 完全同形。

## 四、注意事项：上移 + 精简

⚠️ **注意事项不进 md**（2026-09-28 定）：它就是 `page.html` 顶部手写的那一块 `<mc-alert>`，
**没有第二个副本**，所以不存在「两处手抄、说明文字漂移」的问题（那是 §一 的问题，不是这里的）。
**md 只负责参考区七节**，这里的改动全程不碰 `agent/api/*.md`。

**现状（实测）**：9 页 59 条 —— message 8、breadcrumb 8、card 7、menu 7、tag 7、
alert 6、popover 6、icon 4、code 3、collapse 3；`button` / `color` 两页没有这一节。

**上移的可行性完全依赖精简**：页面顶部放一大块是挡路，不是提醒。目标 **59 → 27 条，
每页 2～3 条**。超过就退回页尾。

**`color="warning"`**（2026-09-28 定）：三角叹号，「用之前该知道」的语气。
`info`（信息圆）太温、`neutral`（灰）不抢戏但不像提醒。

**三刀**（延续 [`doc-pages.md`](./doc-pages.md) §三「落笔前问三句」的写法）：

| #   | 问                                                            | 处理                              |
| --- | ------------------------------------------------------------- | --------------------------------- |
| 1   | **使用者能改吗？** 不能改的（`aria-live` 怎么播报、动画跟系统设置走） | 删 —— 那是实现约束，进组件文件头   |
| 2   | **是「为什么这么设计」还是「你会遇到什么」？**                  | 前者删 / 移 agent-only             |
| 3   | **能压成一行吗？**                                            | 三段式的解释通常有一段是理由、一段是修辞 |

**实例**（从现有 59 条里挑）：

| 保留（真坑）                                            | 删或移（理由 / 实现）                                    |
| ------------------------------------------------------- | -------------------------------------------------------- |
| message：没有 `<mc-message>` 标签可写                   | message：`closable` 不跟 `duration` 推导 —— 设计理由      |
| message：同 key 只留一条，`onClose` 要停掉生产端定时器   | message：容器是 `aria-live`、error 走 `assertive` —— 实现 |
| collapse：头部文案用 `header`，别用 `title`（原生 tooltip） | message：动画跟 `prefers-reduced-motion` 走 —— 实现      |
| breadcrumb：每一级必须是直接子元素，别用 `o-fill` 包      | breadcrumb：`role="listitem"` 由组件补 —— 实现            |
| card：整卡可点自己铺伪元素，`inset` 要取**负的边框宽度**  | card：卡片不投影、层级靠底色明度差 —— 设计决策            |

## 五、渲染器

**落点**：`docs/components/spec.html` —— 站点自己的组件，标签 `doc-spec`
（`doc-` 前缀 + 文件名，同 `nav.html` → `doc-nav`；不写 tag 会按文件名推断出非法元素名，见 P40）。
解析器单独放 `docs/lib/md-spec.mjs`，这样它能被 node 直接单测（`node tests/lib/md-spec.test.mjs`）。
**不放 `packages/`** —— 放进去等于对外发布一个组件，又要配令牌、文档页、API 规范、套件，
反而多两份要维护的文档。

**调用形式**（参考区一个入口，只在页面尾部渲染一次）：

```html
<doc-spec src="./api.md"></doc-spec>
```

**实现要点**：

- **运行时渲染**，`fetch` + URL 缓存（`packages/code/code.html` 的 `loadText(url)` 是现成先例）；
- **自己写受限子集解析器**，不引入通用 markdown 承诺：h1~h3 / 管道表 / 围栏代码 /
  行内 `code`、粗体、链接 / 列表 / 引用块，约 200 行 + 单测；
- 表格输出 `<table class="doc-table">`，保持「第一栏叫名称」「混合表用前缀标种类」的现有口径；
- **相对链接改写**：md 里指向仓库内其它 md 的链接（如 `agent/pitfalls/01-props.md`）按 md
  自身 URL 解析后改成 GitHub 链接，
  否则站点上 404（`docs/pages/specs.html` 已是这个口径）；
- **加载态**：首屏会有一拍异步填充，给固定高度占位，避免回填时页面跳一下。

### 卡点：右栏目录会**静默**丢节

`doc-toc` 收标题走 `contentRoot()` 之后的一次 `querySelectorAll`（`docs/components/toc.html`），
**不下钻嵌套组件的 shadow root** —— 这是既有事实：`doc-cards` 组件化之后卡片墙的分组标题
住进 shadow root，右栏目录从 12 项变 7 项，当时接受了。

这次不一样：参考区**整块**挪进 shadow root，`tests/site/09-doc-toc.mjs` 的断言是
「目录项数 = 页面 h2/h3 数」—— **两边一起变少，套件照样全绿**。这正是这个仓库最怕的静默失效。

→ 必须带一条：让 `doc-toc` **显式下钻这一个已知元素**（不做无差别下钻，否则演示组件内部的
标题会漏进目录），09 号套件改用同一套遍历收集标题，保住「目录 = 正文大纲的镜像，一条不漏」。
