# 组件文档页渲染 API 规范 md：一份源，两处用

> **状态：未定稿、暂停中**（2026-09-27 停在「目标形状」那一轮）。这份只记方向、现状证据与卡点，
> 落地前要把 §六 的三个选择定下来 —— 所以**默认别照着它动手**。
>
> **它要解决的问题**：每个组件的接口事实现在手写两遍。`agent/api/<slug>.md` 里的表格，与
> `packages/<slug>/page.html` 参考区里的表格（10 个页合计 **1527 行 HTML**）是同一批属性 /
> 事件 / 插槽与 part / 令牌，`pnpm check:docs` 还得对两次账。仓库 md 在本文件之前已经 44 份、
> 七千多行，其中约三分之一是 `research/` 与 `docs-refactor.md` 这种「默认不读」的存档。

---

## 一、方向

**md 当唯一手写源：文档页只留例子，参考区由 md 渲染出来。**

- 一份源：`agent/api/<slug>.md` —— 人写、agent 读、页面渲染，三处同一份；
- `page.html` 只剩 `例子`（活的 demos）+ 一个渲染入口；
- 收益：删掉那一千多行手抄 HTML，对账从「两个面」并成「一个面」；
- 顺带守住仓库既有的承诺：**不加构建步骤**，改 md 推上去就是新的（与 `docs/` 现在的做法一致）。

## 二、现状：逐组件规范里能原样渲染的，0 份

13 份逐组件规范里只有 `popover.md` / `message.md` 有 `##` 节标题，其余是「一堆表直接铺」：

| #   | 现状                                                                      | 渲染后会怎样                                                    |
| --- | ------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1   | 大部分文件没有 `##` 节标题                                                | 页面里没有「属性 / 事件 / 插槽与 part」这些节，右栏目录也抓不到 |
| 2   | 节序 = 表格堆放序（button 是 属性→插槽→事件→令牌）                        | 与 `pageSkeleton` 认的顺序不一致，守卫会红                      |
| 3   | 多标签组件用粗体假标题 `**mc-collapse（容器）**`                          | 页面里现在是 `<h3>mc-collapse</h3>` 真标题，目录要少两层        |
| 4   | 正文是 agent 口吻 + 坑号（`[P32](../pitfalls/01-props.md)`）              | 使用者会读到一堆内部编号                                        |
| 5   | `## 实现约束` / `## 刻意不做的`（popover 那一节就有 40 来行）             | 改组件的人才需要，不该摊给使用者                                |
| 6   | 多处 `../` / `../../` 相对链接（含每份文件开头指向 `pitfalls/` 的那一行） | 站点上 404                                                      |
| 7   | 开头 `# mc-button` + `> 共用约定…` + `---` 是 agent 导航                  | 页面里标题重复                                                  |

| 名称 | 值 | 默认 | 说明 |

## 事件

| 名称 | 类型 | 说明 |

| 名称 | 说明 |

**边界规则两条**：第一个 `---` 之上不渲染（agent 开场白 + 简短用法片段）；
`<!-- agent-only -->` 之下不渲染（实现约束 / 刻意不做的）；中间全渲染。

**多标签组件**：`## 属性` 下挂 `### mc-collapse` / `### mc-collapse-item` —— 与页面现有的
`<h2>属性</h2>` + `<h3>mc-collapse</h3>` 完全同形，右栏目录出来的结果与今天一样
（h2 = 节、h3 = 节里的子项）。

## 四、卡点：右栏目录会**静默**丢节

`doc-toc` 收标题走 `contentRoot()` 之后的一次 `querySelectorAll`（见 `docs/components/toc.html`），
**不下钻嵌套组件的 shadow root** —— 这是既有事实：`doc-cards` 组件化之后，卡片墙的分组标题住进
shadow root，右栏目录从 12 项变 7 项，当时接受了。

若参考区改由组件渲染进 shadow root：

- 右栏会悄悄少掉「属性 / 事件 / 插槽与 part / 注意事项」这几节；
- 而 `tests/site/09-doc-toc.mjs` 的断言是「目录项数 = 页面 h2/h3 数」—— **两边一起变少，
  套件照样全绿**。这正是这个仓库最怕的静默失效。

→ 方案必须带一条：让 `doc-toc` **显式下钻这一个已知元素**（不做无差别下钻，否则演示组件内部的
标题会漏进目录），09 号套件改用同一套遍历收集标题，保住「目录 = 正文大纲的镜像，一条不漏」。

## 五、落地清单

1. **补 `##` 节标题**，并把节序统一到 `pageSkeleton` 认的顺序
   （属性 → 事件 → 插槽与 part → 令牌 → 注意事项）；
2. **相对链接改写**：渲染器按 md 自身 URL 解析后改成 GitHub 链接（`docs/pages/specs.html`
   已经是这个口径）；
3. **agent-only 内容**搬进组件文件头注释（[`agent/README.md`](./README.md) 已有这条约定），
   或用 `<!-- agent-only -->` 标记；
4. **解析器**：仓库目前没有任何 md 解析器；`packages/code/code.html` 的 `loadText(url)` 是现成的
   fetch + URL 缓存先例。建议自己写受限子集（h1~h3 / 管道表 / 围栏代码 / 行内 code、粗体、链接 /
   列表 / 引用块，约 200 行 + 单测），不引入通用 markdown 承诺；
5. **渲染入口放 `docs/components/`**（站点自己的组件，`doc-` 前缀），**不要放 `packages/`** ——
   放进去就等于对外发布一个组件，又要配令牌、文档页、API 规范、套件，反而多两份要维护的文档；
6. **守卫改口径**（改 `tools/doc-drift.config.mjs`，不动引擎）：`pageSkeleton` 的参考区口径搬到
   md；`page-api` 面并入 `api-spec`；新增一组「`page.html` 里有渲染入口，且指向存在的 md」。

## 六、要定的三个选择

| #   | 选择       | 备选                                                                                                        |
| --- | ---------- | ----------------------------------------------------------------------------------------------------------- |
| 1   | md 放哪    | 原地 `agent/api/<slug>.md`（改动最小）/ 搬 `packages/<slug>/api.md`（文档跟着组件走，但会进 CDN 产物树）    |
| 2   | 渲染时机   | 运行时（保住「推上去就是新的」）/ 构建期生成进 `page.html`（目录与守卫都不用动，多一个 build + 新鲜度守卫） |
| 3   | 公开区范围 | 令牌表进页面？示例片段进页面？`注意事项` 的内容搬进 md？                                                    |

## 七、和「注意事项只写使用者会踩的坑」的关系

参考区一旦从 md 渲染，`## 注意事项` 的内容就是这份 md 的公开区。所以那次「注意事项去掉实现说明、
只留使用者会踩的坑」（11 页从 72 条删到 60 条，约定见 [`doc-pages.md`](./doc-pages.md) §一）
等于**已经把公开区的内容定了一半** —— 留下的那些就是将来要写进 md 公开区的清单。
