# 怎么给组件加一个令牌

> **这是食谱**：令牌体系的整体规矩在 [`../design-tokens.md`](../design-tokens.md)，
> 这里只讲「给某个组件加一个可覆盖点」要动的三个地方。

例子：给 `mc-tag` 加一个 `--mc-tag-close-hit`（关闭按钮的命中区尺寸）。

---

## 为什么令牌要写进 README 而不是 api.md

令牌**不进文档页**（页面参考区只渲染 api.md 的白名单七节，将来由主题编辑器展示），
所以不能留在 api.md 里当「渲染源里没人渲染的半截」。它归单元 README，
由 `unit-tokens` 那一面对账 —— **加了不写就会红**。

---

## 步骤

**1. 组件 `style` 里声明，默认值引用 L2 语义令牌**

```css
:host {
  /* L3 组件令牌：默认引用 L2 语义令牌。按实例覆盖写在宿主 style 上 */
  --mc-tag-close-hit: var(--mc-space-4);
}
```

命名必须 `--mc-<slug>-` 前缀（对账按这个前缀认领）。
**不许绕过令牌直接写颜色值** —— 组件只消费 L2/L3，不碰 L1 原始色阶。

**2. 如果这个令牌不是给使用者覆盖的**（脚本按几何算好写进来的内部变量），
在行尾标 `@internal`：

```css
--mc-tag-hit-w: 24px; /* @internal：脚本按关闭按钮算好写进来，不是使用者的覆盖点 */
```

标了的令牌**不要求**进文档表（对账会放行）。

**3. `packages/tag/README.md` 的「令牌」表加一行**

```markdown
| 令牌                 | 默认                | 作用                     |
| -------------------- | ------------------- | ------------------------ |
| `--mc-tag-close-hit` | `--mc-space-4`      | 关闭按钮的命中区尺寸     |
```

表头是 `令牌 | 默认 | 作用`。

**4.（可选）演示里演示覆盖** —— 见 [`add-demo.md`](./add-demo.md)。

---

## 验证

```bash
pnpm check:docs   # unit-tokens 面：代码里的令牌文档写了没、文档写的令牌代码有没
```

---

## 这一步最容易踩的

- **令牌前缀写错**（写成 `--mc-close-hit`）→ 对账认领不到，等于没加守卫
- **忘了写 README 那行** → 对账报「代码有、文档没有」
- **文档写了、代码删了** → 反向也会红，别留悬空文档
- 涉及**色板**的新令牌，还要加进 `tools/gen-tokens.mjs`（那是另一条路，见 design-tokens.md）
- 用属性驱动令牌时：`:host(:not([attr]))` 静默失效 —— [P14](../pitfalls/03-style-scope.md)；JS 写的内联样式又会压过 `:host([attr])` 的规则 —— [P15](../pitfalls/03-style-scope.md)
