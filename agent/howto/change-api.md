# 改了接口之后：要同步哪些地方

> **这是食谱**：你已经改完代码，只想把「这次改动该同步哪些地方」走完不漏。
> 这是本项目**最高频**的操作，也是最容易漏的一步 —— 漏了不会报错，
> 只会让文档和代码悄悄脱节（直到某天 `pnpm check:docs` 一片红）。

---

## 先跑这个，让它告诉你漏了什么

```bash
pnpm check:docs
```

它是**双向**对账：代码有文档没有、文档有代码没有，都会报。
改完接口先跑它，比自己回忆清单靠谱。

---

## 对照表：你改了什么 → 要同步什么

| 你改了 | 要同步 | 谁会红 |
| --- | --- | --- |
| 加了 / 删了 / 改名了**属性** | `api.md` 的属性表（名称 / 值 / 默认） | `api-spec` 面 |
| 改了属性的**默认值** | 同一张表的「默认」列 | `api-spec` 面（对第 3 列） |
| 加了 / 删了**事件** | `api.md` 的事件表（名称 / 类型 / 说明） | `api-spec` 面 |
| 加了 / 删了**插槽或 part** | `api.md` 的插槽与 part 表 | `api-spec` 面 |
| 加了 / 删了**组件令牌** | `README.md` 的令牌表 | `unit-tokens` 面 |
| 加了 / 删了**演示** | `page.html` 的 `<l-m>` 与演示区段落 | 05 号套件 |
| 命令式组件：加了**方法 / 配置项** | `api.md` 的方法表 / 配置表 | `api-spec` 面的 imperatives |
| 改了**里程碑**（M1 → M2） | `docs/site-map.js` 的 `stage` | `unit-readme` 面（README 状态对账） |

**不该动的地方**：

- `README.md` 里**不许**出现 `属性` / `事件` / `插槽` / `part` 这类节标题 ——
  接口事实的唯一手写源是 `api.md`，写了就是第二份会漂移的副本（`unit-readme` 守卫会拦）
- `page.html` 里**不许**再手抄参考表格 —— 参考区由 `<doc-spec src="./api.md">` 渲染
- 组件本体头注释**不许**超过 8 行 —— 设计说明归 README 的「设计取舍」

---

## 常见报错怎么读

| 报错 | 意思 | 怎么修 |
| --- | --- | --- |
| `代码有、文档没有：xxx` | 你加了属性没写进 api.md | 补表那一行 |
| `文档有、代码没有：xxx` | 你删了属性没删表 | 删表那一行 |
| `默认值不符：文档 xxx / 代码 yyy` | 改了代码默认没改表 | 改表的「默认」列 |
| `令牌 --mc-x-y 不在文档表里` | 加了令牌没写 README | 补 README 令牌表（或标 `@internal`） |
| `README 里出现了「属性」节` | 接口事实抄进 README 了 | 删掉，它归 api.md |
| `页面里出现了手写的属性表格` | 回潮了 | 删掉，只留 `<doc-spec>` |

## 验证（提交前跑）

```bash
pnpm check:docs            # 16 组全绿
node tests/smoke.mjs <slug> # 只跑这次命中的组件
```

全量测试只在收尾跑一次 —— 中途重复全量既慢，又会掩盖「这次改动影响了什么」
（默认就是选测 `pnpm test`；加 / 挪了套件先 `pnpm test:record`；收尾跑 `pnpm test:all`）。

## 这一步最容易踩的

改接口时连带踩到的几条（都不报错，靠对账才发现）：

- 加的是**布尔属性**，默认值要写 `null` 不是 `false` —— [P1](../pitfalls/01-props.md)
- 声明过的**字符串属性**会被 ofa 以空值写到宿主上，别假设「没写就没有」 —— [P32](../pitfalls/01-props.md)
- 新发的**合成事件要带 `{ composed: true }`**，否则穿不出 shadow —— [P22](../pitfalls/04-dom-events.md)
- 插槽 / part 的样式，`::slotted()` 压不过祖先 shadow 树的规则 —— [P33](../pitfalls/03-style-scope.md)
