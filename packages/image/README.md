图像。一个图框：填充方式、圆角、宽高比可配，点开看大图；图片组里预览能左右切；失败落到 alt 或插槽。

## 设计取舍

**宿主是框，图片铺满。** 组件不接管排版：盒子大小由使用者给（`style="width/height"`），或者写了 `ratio`
之后按父级宽度算高；内部 `<img>` 恒为 `width/height: 100%`，`fit` 只决定它怎么落进这个框（`object-fit`）。
不给盒子时宿主按图片原始尺寸落版（`inline-block` + `max-width: 100%`：百分比宽高在收缩盒里各自退回
内容尺寸，所以「不给尺寸 = 原图大小」不需要脚本量一遍）。

**三个状态都镜像到宿主：** `data-loading` / `data-has-image` / `data-error`（P32），CSS 只认这三个属性。
换地址先回「加载中」，等 `load` / `error` 再定状态；失败时内部 `<img>` 直接 `display: none` ——
否则浏览器会把破图标和 alt 一起画进框里，再让兜底层盖上去就会出现两份文字。

**兜底文字取 `alt`，插槽两级都优先。** 和 [`mc-avatar`](../avatar/) 同一条：avatar 拿 `name` 生成首字母，
image 拿 `alt` 当文字。插槽分两级 —— 具名 `fallback` 槽给「图标 / 按钮」这类结构，默认插槽给一句话，
取第一个有内容的（`data-has-named` / `data-has-fallback`）。插槽不渲染时（图正常显示）它在 shadow 里
根本不出现，所以不需要额外隐藏。

**预览是整页一个浮层。** 点开走原生 `popover` 进 top layer（和 [`mc-dialog`](../dialog/) 同一条路子），
但挂在 `document.body` 上、不住组件 shadow 里 —— 住在 shadow 里就会被宿主的 `overflow: hidden`
（圆角裁切）和祖先的层叠上下文裁掉。浮层做成单例（`preview.js`，不是标签、不进 `api.md`）：
一个页面几十张图各带一层会叠成迷宫，而且「上一张 / 下一张」只能有**一个**游标。打开时把
「列表 + 起点」交给它：`mc-image` 给单张，组内给整组成员。三条关闭路径（× / Esc / 点遮罩）都汇到
`toggle` 事件里收尾一次 —— 浏览器自带的 Esc 也走那儿，两条路各清一次状态就会漏焦点归还。

**组不存状态，只提供两个事实。** `mc-image-group` 自己不记任何东西：成员范围与 `loop` 都是
`mc-image` 打开预览时回去问的（`closest('mc-image-group')` + `querySelectorAll('mc-image[preview]')`）。
这样组里可以夹别的元素、图片可以晚挂载，也不会出现「组和子项状态不同步」。代价是成员必须写在组里面；
跨层也认（卡片里包一张图照样进组），嵌套的组各管各的（`closest` 取最近的）。组也没有 `part` ——
宿主本身就是排图容器，要改间距写 `--mc-image-group-gap`，要改别的直接给它 `style` / `class`。

**可点就得键盘可达。** `preview` 且有图时宿主带 `role="button"` + `tabindex="0"`，Enter / Space 等价于点击，
焦点环用 `--mc-color-ring`（P16）；图失败时这些属性撤掉 —— 一张坏图不该是能聚焦的按钮。

**刻意不做的：** 预览的缩放 / 旋转 / 下载（先做「点开看大图」的最小闭环，双指缩放交给浏览器 ——
浮层里就是原图）、`preview-src`（预览换另一张大图：要省流量该用 `srcset` 让浏览器挑，不是再加一个属性）、
`srcset` / `sizes`（响应式选图应该由页面按场景决定，组件再包一层只是把原生能力藏起来）、
加载中的骨架动画（那是 [`mc-skeleton`](../skeleton/)）、失败重试按钮（同一个地址不会自动重试，
换地址或清空再写才会重新加载）。

**已知边界。** 失败且没给盒子高度时，框会缩到兜底文字那么高 —— 图本来就没有尺寸了，只能按内容撑；
要给固定占位就在宿主上写 `height`，或用 `ratio` 把高度锁死。

## 令牌

| 令牌                        | 默认                                             | 作用                                  |
| --------------------------- | ------------------------------------------------ | ------------------------------------- |
| `--mc-image-radius`         | `--mc-radius-none`（sm / md / lg / full 各一档） | 圆角；`overflow: hidden` 把图裁进去   |
| `--mc-image-placeholder`    | `--mc-color-surface-sunken`                      | 加载中 / 失败时垫的底色               |
| `--mc-image-fallback-color` | `--mc-color-fg-muted`                            | 兜底文字颜色                          |
| `--mc-image-ratio`          | 由 `ratio` 写进宿主（如 `16/9`）                 | `aspect-ratio` 的取值；清空属性才撤掉 |
| `--mc-image-group-gap`      | `--mc-space-2`                                   | 图片组里图与图的间距                  |

预览浮层的配色不走组件令牌（它挂在 shadow 外）：遮罩恒为 90% 黑、控件恒为半透明白 —— 深色浅色主题
里都成立，也就不需要跟着主题切换。

## 相邻单元

- 与 [`mc-avatar`](../avatar/) 的分工：avatar 是「身份」的小图（内置首字母兜底、形状与尺寸档位、语义色），
  image 是内容图 —— 管的是框与填充，兜底只认 `alt` 与插槽，不内置尺寸档位。
- 与 [`mc-dialog`](../dialog/) 的分工：dialog 是「有内容、要决策」的模态框（标题 / 头身脚 / 焦点陷阱），
  image 的预览只承载一张图 —— 同一条 popover 路子，但预览不做焦点陷阱、也不放按钮区。
- 与 [`mc-skeleton`](../skeleton/) 的分工：加载中的动画占位是 skeleton 的活；image 只留一块静态底色，
  图到了就换掉，两者可以叠在一个位置上接力。
- 与 [`mc-empty`](../empty/) 的分工：empty 是「整块区域没有内容」的占位（图 + 文案 + 操作区，
  由容器决定出现在哪），image 的兜底只顶替一张图，不负责整页空态。
