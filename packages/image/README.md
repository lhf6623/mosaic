# mc-image（图像）

> **这是单元开发文档，不是接口文档。** 接口事实（属性 / 方法 / 事件 / 配置 / 插槽 / part）

> 并放**不进文档页**的东西（令牌 / 实现约束 / 刻意不做的）—— 那些是改代码的人才要看的。

**状态**：已实现 · 标签 `mc-image` · 目录 `packages/image/`

图像。一个图框：填充方式、圆角、宽高比可配，点开看大图；图片组里预览能左右切；失败落到 alt 或插槽。

## 设计取舍

**宿主是框，图片铺满。** 组件不接管排版：盒子大小由使用者给（`style="width/height"`），或者写了 `ratio`
之后按父级宽度算高；内部 `<img>` 恒为 `width/height: 100%`，`fit` 只决定它怎么落进这个框（`object-fit`）。
不给盒子时宿主按图片原始尺寸落版（`inline-block` + `max-width: 100%`：百分比宽高在收缩盒里各自退回
内容尺寸，所以「不给尺寸 = 原图大小」不需要脚本量一遍）。

**三个状态都镜像到宿主：** `data-loading` / `data-has-image` / `data-error`（P32），CSS 只认这三个属性。
换地址先回「加载中」，等 `load` / `error` 再定状态；失败时内部 `<img>` 直接 `display: none` ——
否则浏览器会把破图标和 alt 一起画进框里，再让兜底层盖上去就会出现两份文字。

**兜底文字取 `alt`，插槽两级都优先。** 和 [`mc-avatar`](../avatar/) 同一条：avatar 拿 `name` 生成首字母，
image 拿 `alt` 当文字。插槽分两级 —— 具名 `fallback` 槽给「图标 / 按钮」这类结构，默认插槽给一句话，
取第一个有内容的（`data-has-named` / `data-has-fallback`）。插槽不渲染时（图正常显示）它在 shadow 里
根本不出现，所以不需要额外隐藏。

**预览是整页一个浮层。** 点开走原生 `popover` 进 top layer（和 [`mc-dialog`](../dialog/) 同一条路子），
但挂在 `document.body` 上、不住组件 shadow 里 —— 住在 shadow 里就会被宿主的 `overflow: hidden`
（圆角裁切）和祖先的层叠上下文裁掉。浮层做成单例（`preview.js`，不是标签、不进 `api.md`）：
一个页面几十张图各带一层会叠成迷宫，而且「上一张 / 下一张」只能有**一个**游标。打开时把
「列表 + 起点」交给它：`mc-image` 给单张，组内给整组成员。关闭路径（工具条关闭按钮 / Esc / 点遮罩 /
浏览器自带的 popover 关闭）都汇到 `toggle` 事件里收尾一次 —— 两条路各清一次状态就会漏焦点归还。
**起点归一与 `open` 载荷只在 `openPreview()` 里生成一次**：滤掉空 `src`、越界夹到两端之后，
外面已经算不准最终是第几张（列表会被过滤、`index` 可能是 -1），所以它返回归一后的
`{ src, index, total }`（一张图都没有时返回 `null`），两个入口拿返回值发事件 ——
各自再夹一遍只能「碰巧」一致。

**工具条只有底部一条。** 导航（有第二张才出现）、缩放、旋转、还原、下载、关闭全在一条胶囊里：
浮层只给一套控制面，位置固定，比在四个角各摆一个按钮更好找。缩放走固定档位
（50% → 400%，`+` / `-` / 滚轮，双击图在 1 倍与 2 倍间跳），旋转 90° 一档（`R`，`Shift+R` 反向），
`0` 还原。转 90° 时把 `max-width` / `max-height` 对调 —— 横图竖过来还能整幅落在框里，
不对调就会一头顶出屏幕。换图时缩放、角度、位移一起归位：上一张的放大状态带到下一张只会让人莫名其妙。
下载先 `fetch` 成 blob 再存（`download` 属性只对同源生效，跨域直接点会变成跳转），
拿不到 blob 就退回新标签页打开 —— 不让按钮变哑巴。

**旋转角度必须累加，不能取模。** `transform` 的过渡按**数值**插值：从 `rotate(0deg)` 到
`rotate(270deg)` 浏览器会顺时针转 3/4 圈 —— 看着就像「按左转却右转了好几圈」。所以 `angle`
一路累加（`-90`、`-180`……），每步只差 ±90，方向永远和按钮一致；「是不是已经转正」用
`foldDeg()` 折回 `(-180, 180]` 再判断。攒大了只在还原前折一次：折算时关掉过渡
（`.mcp-no-anim`）并强制落一帧，动画才从折后值起步 —— 否则从 `-450` 回 `0` 要逆时针转一圈多。

**放大之后按住能拖。** 位移记在**框的坐标系**里（`translate3d` 写在 transform 最左边）——
写在右边会被旋转和缩放一起放大，转 90° 之后横向拖就变成了上下动。可拖的余量 =
图片（旋转 + 缩放后）外接框比框大的那部分的一半，两个轴各算各的：
图没超出框的那个轴余量恒为 0，一张正好尺寸的图不会被拖进黑边里，越拖越歪。
外接框按 `w·|cos| + h·|sin|` 算旋转后的宽高，转 90° 就等于把宽高对调，与 `max-*` 的对调是同一件事。
缩放 / 旋转之后位移会夹回新范围（缩回 100% 自动居中），换图与还原一律归零。

拖动本身走 pointer 事件 + 指针捕获：鼠标 / 手指 / 触控笔一套代码，拖出框外、拖到工具条上都不会断。
两个必须做的细节：**拖动期间关掉 `transition`**（开着 0.18s 缓动，图会慢半拍追着指针爬，像在打滑）；
**松开那一下紧跟的 click 要吃掉**（拖完在遮罩上松手，不改这一下就顺手把浮层关了）。
余量在每个 `pointermove` 里重量一次是浪费 —— 按下时量一次存进拖动状态，拖动过程中范围不会变。

**组不存状态，只提供两个事实。** `mc-image-group` 自己不记任何东西：成员范围与 `loop` 都是
`mc-image` 打开预览时回去问的（`closest('mc-image-group')` + 组里全部 `mc-image` 再滤掉
`preview-disabled`）。
这样组里可以夹别的元素、图片可以晚挂载，也不会出现「组和子项状态不同步」。代价是成员必须写在组里面；
跨层也认（卡片里包一张图照样进组），嵌套的组各管各的（`closest` 取最近的）。组也没有 `part` ——
宿主本身就是排图容器，要改间距写 `--mc-image-group-gap`，要改别的直接给它 `style` / `class`。

**组只多一个方法 `open(index)`，不开自己的浮层。** 它把「从第几张开始」转给那一张 `mc-image` 的
`open()` —— 起点、整组范围、`loop` 都在那张图上，组不必再传一遍。`index` 数的是**能进相册的成员**
（`preview-disabled` 的不算），所以和组里 `mc-image` 的文档顺序不一定一一对应，这是刻意的：调用方
关心的是「第几张图」，不是「第几个子节点」。

**三个标签都有 `open()`。** `mc-image.open()` 是「从这张开始」（组内仍能左右走完），
`mc-image-group.open(index)` 是「从组里第 index 张开始」，`mc-image-preview.open(index)` 是
「从自己的列表第 index 张开始」。
主动调用**不过**点击那道门：`preview-disabled` 的图自己也能被 `open()` 打开（只是它不进别人的相册），
没加载完的图也能开（浮层里会显示失败兜底）。默认 `opener` 取调用那一刻的焦点元素 —— 按钮调的，
关掉之后焦点就回到那个按钮，调用方不用传参。

**预览默认开，开关写成正向的 `preview-disabled`。** 一张图最常见的期待就是「点开看大图」，所以不写属性
也算开；装饰性、纯排版的图写个 `preview-disabled` 一键退出，不必为「不要交互」再去改结构。

选正向属性不是为了好看：ofa 的布尔绑定把 `false` 写成 `attr="false"` 而不是删掉属性
（`packages/README.md` 1.4），所以「默认开」的开关若是 `preview="false"` 就得写一个**反向**读法
（`getAttribute('preview') !== 'false'`），而 `:preview="whatever"` 这种非布尔值也全算关。换成
`preview-disabled` 之后，`flag()` / `boolAttr()` 那套现成读法直接可用，`:preview-disabled="false"`
自然等于「开」。CSS 那边不认 `="false"`，所以能不能点由脚本镜像成 `data-preview-on`（P32）。

**可点就得键盘可达。** 没写 `preview-disabled` 且有图时宿主带 `role="button"` + `tabindex="0"`，
Enter / Space 等价于点击，焦点环用 `--mc-color-ring`（P16）；图失败时这些属性撤掉 ——
一张坏图不该是能聚焦的按钮。

**不展示的图，把预览挂到按钮上。** `mc-image-preview` 是同一个浮层的第三个入口，本体 `display: none`：
没有盒子所以不占位，不在无障碍树里，也聚焦不到 —— 它存在的唯一意义是「交出列表 + 起点」。列表两种写法：
宿主自己的 `src` / `alt`（一张），或子元素（`<img>` / `<mc-image>`，多张，只读它们的属性、不渲染）。

**它只给方法，不给触发器属性。** `open(index?)` / `close()` 挂在宿主上，接哪个按钮、什么时候开，
由使用者那次点击决定（`on:click` 里调一下，或者任意逻辑里拿到实例调）。刻意没做 `trigger="#id"`
那种「写个选择器、document 上挂委托」的写法：为了一个「点一下」去挂全局点击监听，得处理晚挂载、
宽选择器把浮层自己的按钮也命中、`composedPath` 穿透 shadow、非法选择器吞异常 —— 代价全在组件里，
而 `open()` 一个方法就把同样的能力交到调用点手上，调用点的代码还是最短的那一行。

**不传 `opener` 也能还焦点。** `open()` 打开时记下当时的 `document.activeElement`（一路钻进 shadow，
所以点 `<mc-button>` 记到的是里面那个 `button`），关闭时还给它 —— 「关闭后焦点回到按钮上」不需要
调用方配合。要还别的元素就显式传第二个参数。还焦点排到下一帧：popover 隐藏后浏览器那趟焦点清理
是异步的，同步 `focus()` 会被它盖掉。

**刻意不做的：** 双指缩放（浮层里就是原图，触控板 / 滚轮已经够用，手势捏合会跟浏览器自己的缩放打架）、
拖动时的惯性滑动（松手继续滑需要一条动画队列与减速曲线，看大图的场景里收益很低）、
`preview-src`（预览换另一张大图：要省流量该用 `srcset` 让浏览器挑，不是再加一个属性）、
`srcset` / `sizes`（响应式选图应该由页面按场景决定，组件再包一层只是把原生能力藏起来）、
加载中的骨架动画（那是 [`mc-skeleton`](../skeleton/)）、失败重试按钮（同一个地址不会自动重试，
换地址或清空再写才会重新加载）。

**已知边界。** 失败且没给盒子高度时，框会缩到兜底文字那么高 —— 图本来就没有尺寸了，只能按内容撑；
要给固定占位就在宿主上写 `height`，或用 `ratio` 把高度锁死。

## 令牌

| 令牌                        | 默认                                             | 作用                                  |
| --------------------------- | ------------------------------------------------ | ------------------------------------- |
| `--mc-image-radius`         | `--mc-radius-none`（sm / md / lg / full 各一档） | 圆角；`overflow: hidden` 把图裁进去   |
| `--mc-image-placeholder`    | `--mc-color-surface-sunken`                      | 加载中 / 失败时垫的底色               |
| `--mc-image-fallback-color` | `--mc-color-fg-muted`                            | 兜底文字颜色                          |
| `--mc-image-ratio`          | 由 `ratio` 写进宿主（如 `16/9`）                 | `aspect-ratio` 的取值；清空属性才撤掉 |
| `--mc-image-group-gap`      | `--mc-space-2`                                   | 图片组里图与图的间距                  |

预览浮层的配色不走组件令牌（它挂在 shadow 外）：遮罩恒为 90% 黑、控件恒为半透明白 —— 深色浅色主题
里都成立，也就不需要跟着主题切换。

## 相邻单元

- 与 [`mc-avatar`](../avatar/) 的分工：avatar 是「身份」的小图（内置首字母兜底、形状与尺寸档位、语义色），
  image 是内容图 —— 管的是框与填充，兜底只认 `alt` 与插槽，不内置尺寸档位。
- 与 [`mc-dialog`](../dialog/) 的分工：dialog 是「有内容、要决策」的模态框（标题 / 头身脚 / 焦点陷阱），
  image 的预览只承载一张图 —— 同一条 popover 路子，但预览不做焦点陷阱，工具条只伺候这张图本身。
- 与 [`mc-skeleton`](../skeleton/) 的分工：加载中的动画占位是 skeleton 的活；image 只留一块静态底色，
  图到了就换掉，两者可以叠在一个位置上接力。
- 与 [`mc-empty`](../empty/) 的分工：empty 是「整块区域没有内容」的占位（图 + 文案 + 操作区，
  由容器决定出现在哪），image 的兜底只顶替一张图，不负责整页空态。
