# 组件文档页规范：页面骨架 · 演示区 · 参考区 · 首页

> 这是 [packages/README.md](./README.md) 的「页面规范」部分，从总纲拆出来单独维护。
> **读这份的场合**：写 / 改任何组件文档页（`packages/<slug>/page.html`）、增删演示、改
> `<doc-example>` / 「普通例子」的用法时。
> 组件接口共用约定（属性 / 事件 / 插槽 / part / 键盘）见 [README.md §五](./README.md)；
> 逐组件接口事实住各自单元的 [`api.md`](./button/api.md)。

---

## 一、页面骨架：开场白 → 例子 → 参考区（由 `api.md` 渲染）

**文档页只写用法。** 每一页都按下面的顺序排，读的人不用在几种排法之间找。
**页面源码里只有一个 `<h2>`：`例子`** —— `属性` / `事件` / `插槽` / `part` 四个参考节由本单元的
[`api.md`](./button/api.md) 经 `<doc-spec>` 运行时渲染，**页面里不手抄一张表**
**没有内容可写的节整节省略** —— 尤其别为了凑一节
写一句「用户自己看得见」的废话（导语只在「一眼看不出来」时才写）。

| 顺序 | 块                              | 放什么 / 从哪来                                                                                                                                                                  |
| ---- | ------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | 开场白                          | `<h1>Xxx <code>mc-xxx</code></h1>` + 一句 `.doc-lead`                                                                                                                            |
| 2    | `例子`                          | 全部 `<section class="doc-demo">`，包在一层 `<doc-demos>` 里（宽屏按最短列流式排、窄屏一列；每个演示：标题 →（可选）说明 → 可编辑示例）—— 页面源码里唯一的 `<h2>`                |
| 3    | **参考区**（`<doc-spec>` 渲染） | 页面尾部 `<doc-spec src="./api.md"></doc-spec>`：md 白名单四节（`属性` / `事件` / `插槽` / `part`）渲染成同名的 `<h2>`，只放表；方法行并进事件表、配置表并进属性表（口径见 §三） |

⚠️ **页面顶部没有「注意事项」那一块了**（2026-10 去掉的）：它是个自由填写的桶，口径只能钉条数（「每页 2～3 条」），
实际每次都靠感觉拿捏 —— 一半是 `api.md` 里本来就查得到的复述，一半是真坑。
现在**坑写进它真正会踩到的那个演示的导语**（`.doc-hint`）：真属于某个演示的才写，没有对应演示的就别上页面。

⚠️ **没有「定制」节了**（2026-09 去掉的）：L3 令牌清单**不进文档页、也不进 `api.md`** ——
它住在单元 [`README.md`](./button/README.md) 的令牌表里（`unit-tokens` 面对账），
将来由主题编辑器展示。页面上的用法由「外部样式」（宿主 `style` / 令牌）与
「内部样式」（`::part()`）两条演示承担。**别再往文档页里加令牌表** —— 那一节原来叫
`定制：L3 令牌 + ::part()`，标题与演示重复，表格又和规范里那份重复。

⚠️ **参考表的第一栏一律叫「名称」**：表头别复述节标题（原来属性表的第一栏就叫「属性」、事件表叫「事件」），
`名称` 说明的是「这一格填的是接口名」，放在哪一节都成立：属性表 / 事件表 / 插槽表 / part 表
第一栏都是 `名称`。（`令牌` 是数据字段名，不进这些表 —— 见上面那条。）

⚠️ **为什么事件要单开一节**：它原来混在属性表那一节里、连 `<h2>` 都没有（collapse 的事件表挂在
`mc-collapse-item` 属性表下面），右栏目录里根本看不到它 —— 而「怎么监听」恰恰是最常查的东西之一。
**命令式入口的「方法」也并进这一节**（2026-10 收的）：`loadingBar.start()` / `show()` 这类调用写在
同一张表里，名称写调用式、类型写 TS 签名（见 §三）。

- 正文最前是 `<l-m>` 注册（本组件 + 页面用到而外壳没注册的组件；**演示不用注册**，页面写
  `<doc-example src>` 即可）；之后依次是 `<h1>` / `.doc-lead`、
  `<h2>例子</h2>`、`<doc-spec src="./api.md">`。
- 页首只留 `<h1>` + 一句 `doc-lead`，**不要把参考表写在例子前面**：
  先看能做什么（例子），再查怎么配（参考区）。
  ⚠️ **页首没有徽标了**（2026-09 去掉的 `doc-badges`）：「已实现 / `packages/xxx/`」这类胶囊
  每个组件页都写死同一份、且与导航数据（[`site-map.js`](../docs/site-map.js) 有没有 `path`）重复，
  文档页不再单独抄一遍。
- 实现说明（为什么这么分层、底层用了什么机制）不进文档页 —— 留在组件文件头与同单元 `README.md` 的「设计取舍」节。
- 每个演示的标题与 `.doc-hint` 留在 `<section>` 里；演示之间不插属性表。
- **`<mc-code>` 文本是逐字展示的**（「色彩」页那种内联样例、以及 demo 文件里演示 `mc-code`
  的样例）—— 整份 `packages/*/demos/*.html` 都在 `.prettierignore` 里（2026-10 定的：
  `pnpm format` 曾把 7 个 demo 的样例挤行，code 套件连挂 4 条），所以内联样例直接写、
  **不需要 `<!-- prettier-ignore -->`**；代价是这些 demo 的 `<script>` 与属性折行也得手写保持风格。
  长片段改用 `src="…"` 仍然更省事。
  ⚠️ `.prettierignore` 只有 **Prettier** 认：编辑器用的格式化器不是 Prettier（VSCode 没装 /
  没用 Prettier 扩展时，「格式化文档」走的就是内置那份）时它照旧会重排 —— 块内多个空格被并成一个、
  相对缩进被抹平。块里是要**逐字展示**的原文，重排 = 文档内容变了（`mc-code` 只 dedent 掉最小公共
  缩进，少掉的 2 空格就是渲染出来的层级）。改这几个文件前确认编辑器用的格式化器是 Prettier
  （即 `pnpm format` 跑的那份）。

## 二、演示区三段：标题 → 说明 → 可编辑示例

顺序固定，读的人不用在几种排法之间找：

```html
<!-- 所有演示区先包一层 <doc-demos>：宽屏按列流式排、窄屏一列，只算位置不搬 DOM，
     标题顺序与右栏目录始终一致；漏了这层会退回「一条一条竖着排」 -->
<doc-demos>
  <section class="doc-demo">
    <h3>语义色</h3>
    <!-- ① 标题：中文名，尽量短，不带英文（英文去属性表里查） -->
    <p class="doc-hint">六个语义色，颜色是按钮唯一决定「语气」的维度。</p>
    <!-- ② 说明：可选。是导语不是脚注，写「在看之前该知道什么」 -->
    <doc-example src="./demos/colors.html"></doc-example>
    <!-- ③ 可编辑示例：组件读这份文件做初始预览；展开后的编辑 / 运行 / 重置都基于同一份源 -->
  </section>
</doc-demos>
```

**`<doc-demos>` 这层不能省。** 它是演示区的布局容器（`docs/components/demos.html`）：宽屏按列流式排、窄屏一列；
漏掉时页面不会报错，只会退回「一条一条竖着排」的老样子 —— `page-skeleton` 守卫查不出来，只能靠这条约定。

- **① 标题 = API 名的中文，尽量短**：一个演示讲一个属性 / 插槽 / 事件时，标题就是它的中文名
  （`尺寸`、`禁用`、`手风琴`、`自定义头部`）。英文属性名不进标题 —— 那是属性表的事，
  标题写全了只会把右边的目录撑长。
  只有这几类允许不是「单个 API 的中文名」：`基本用法`、样式类、结构 / 组合用法（如 `嵌套`）。
  样式类的名字要**一看就知道改哪儿**，且不跟别的词混：`外部样式`（宿主 `style="…"`）/
  `内部样式`（`::part()`）—— ~~`定制样式`~~ 看不出改什么，~~`定制外框`~~ 容易被读成「边框」。
  ⚠️ 一条演示只讲一种机制，别把两者并成一条：并了之后导语必然承诺演示没做的事
  （原来 collapse 那条叫 `定制样式`、导语写着 `::part()`，可演示文件里只有 `style="…"`）。
  ⚠️ 标题同时是**右栏目录的文案**（`doc-toc` 扫 h3），改成又长又绕的词会连带影响那条宽度预算。
- **第一条演示固定是 `基本用法`，而且是「最小可信用法」**：把「没有它这个组件就用不了」的
  最基本属性先摆出来 —— `mc-table` 的 `columns` + `data`、`mc-menu` 的 `options`、
  `mc-tabs` 的 `mc-tab` 子项、`mc-popover` 的触发元素 + `slot="panel"` 面板、`mc-icon`
  的 `name` —— 让人先看到组件「能跑」；颜色 / 尺寸 / 状态 / 变体这些维度留给后面的专节。
  首条原本按某个维度命名（`语义色` / `方位` / `竖向滚动`）的页，补一条 `基本用法` 排到它前面；
  令牌 / 主题页（`color`：没有组件标签、也没有 `demos/`）不适用这条。
  ⚠️ **文件和标签也固定**：文件名就是 `packages/{slug}/demos/basic.html`，`tag` 随之是
  `demo-<slug>-basic`（其余演示同理 `demo-<slug>-<文件名>`，全仓演示都按这条命名；改名要连
  页面 `src`、测试里的宿主选择器、`tests/suite-map.json` 一起改）。
- **② 说明是导语，而且可选**：它在组件**之前**，写「这个例子在演示什么、该看哪儿」。
  **一眼就看得明白的例子不要写**（三档尺寸、两种外观这种），写了反而是噪声；
  反过来，「看不出来」的信息必须写在这里（键盘怎么操作、禁用之后焦点会怎样、
  `$event.data` 里有什么）—— 演示区里没地方放这些。
  会踩的坑写进**它真正会踩到的那个演示**的导语里（页面顶部不再有「注意事项」那一块）；没对应演示的坑就不上页面。
  ⚠️ 概念解释**全页只写一遍**，放在读者**第一次遇到那个词**的地方。例子区在参考区前面，
  所以术语的定义落在导语里：`part` 是什么写在「内部样式」的导语中，
  「插槽」/「part」节**只放表**（参考区不写解释句，读者从例子过来时已经懂了）。
  ⚠️ **导语不复述示例**：别把演示展开后已经写着的句子再抄一遍（导语与演示正文撞车＝同一条信息两遍）。
  示例代码 / 演示正文已经展示的属性、参数、行为，导语不再说一遍；只补「看不出来」的信息
  （键盘、焦点、载荷、边界、坑）。判断法：把导语删掉，读者照着示例还能不能懂？能懂 → 删掉。
  Code Editor 这类「看代码就知道在演示什么」的页尤其适用。
  它在演示区里的间距由 `content.css` 的 `.doc-demo > .doc-hint` /
  `.doc-demo doc-example .doc-hint` 给。
- **③ 可编辑示例是一个独立的 ofa 组件文件**（`demos/*.html`）：可单独打开、单独测，一个演示
  一个文件。演示写 `<doc-example src="./demos/x.html">`；要给「普通例子」视图时再加
  `plain-src="./demos/x-plain.html"`（见 §二末）——
  **都不写 `<l-m>`、也不写 `<demo-x>` 标签**：组件自己读这份文件、运行时编译出初始预览，
  展开后的编辑 / 运行 / 重置都用同一份源，没有第二份片段会漂移。
- ⚠️ **标题与 `.doc-hint` 必须留在页面里**：`doc-toc` 只扫页面 shadow root 的 `h2` / `h3`，
  收进可编辑示例组件会让整页目录少掉所有演示标题（同 `doc-spec` 的理由）。
- ⚠️ **`demos/*.html` 仍整份在 `.prettierignore` 里**：演示内部可能用 `<mc-code>` 逐字展示
  代码片段，prettier 会把换行压掉（2026-10 全仓格式化挂过 code 套件 4 条）。与编辑器无关了，
  但这条忽略继续有效，也别给 demo 文件加逐块 `prettier-ignore`。

> **迁移状态**：全部组件文档页已按这个结构排过（开场白 → 例子 → `<doc-spec>` 参考区 → 页脚）。
> 所有演示都已迁到 `<doc-example>`；「基本用法」还各配一份同目录的 `basic-plain.html`（普通例子）。
> 演示区的段落顺序就是这份指纹（`h3|example` / `h3|hint|example`）—— 说明可以在、可以不在，
> 但**绝不许落在示例之后**；参考区渲染出来的节与 `api.md` 逐条对账。

⚠️ **覆盖线**：组件代码里有的**属性** / **命名插槽** / **part**，都至少要有一个演示真的用到它 ——
属性直接写、插槽写 `slot="x"`、part 用 `::part()` 改（就是这一页的「内部样式」），`demo-covers-api` 守着。
它**不是**「一条演示只讲一个属性」：同一维度的变体（三档尺寸、六个颜色）合一条照样算覆盖；
反过来，加了属性 / 插槽 / part 却没演示，这里就红。

**例子住在 `packages/{name}/demos/*.html`，一个演示一个文件**，文件本身就是
ofa.js 组件（`<template component>` + 一行 `tag`）；页面只按 `src` 引用它，
**不写 `<l-m>`、也不写标签**：

```html
<!-- demos/colors.html -->
<template component>
  <mc-space block wrap-items>
    <mc-button color="primary">主要</mc-button>
  </mc-space>
  <script>
    export default async () => ({ tag: 'demo-button-colors' });
  </script>
</template>
```

- **演示文件不参与 `pnpm format`**（在 `.prettierignore` 里）：里面的 `mc-code`
  文本是逐字展示的样例代码，prettier 会把它的换行压掉（实测 JSON 被压成两行、
  bash 丢了所有换行）。它本身就是要展示的内容，照旧手写。
- **一个演示文件只讲一件事。** 同一件事的多个变体可以放一起（六种颜色、三档尺寸），
  但**两个不同的 API / 特性要拆成两个文件、两节**（`max-height` 与 `soft-wrap`、
  `code` 属性与 `:code` 绑定）—— 一个文件里塞两件事，可编辑示例给出的就不是一个
  能直接抄的例子了。
- **只有一份源**：`<doc-example src="./demos/x.html">` 读的就是上面那份文件 ——
  初始预览、编辑器里的文本、重置都用它；改例子 = 改文件，**没有第二处会漂移**。
- **例子是组件，不是片段**，所以它里面的 ofa 绑定照常编译（`:code="boundSnippet"`、
  `on:open="…"`），而且**可以单独打开、单独测**（`doc-example` 按组件规范编译文件，
  不是把 `innerHTML` 塞进去）。
- 例子的 DOM 在自己的 shadow root 里，**页面级的 `.doc-row` 这类样式够不着** —— 例子内部的
  排版优先用 `mc-space`（站点外壳已注册），其余工具类照常用（`text-sm`、`p-4` 这些）。
- **成组排列优先用 `mc-space`**：行 / 列、间距、换行、主轴与交叉轴对齐都交给它；不要再手写
  `flex flex-col gap-3` 这类布局工具类。`gap` 可写三档令牌或数字（px）。
- **能用默认值就不写属性**：默认 `gap` 是 `md`（16px），横向 `align="center"`、`justify="start"`
  也都是默认 —— 不写；只有需要非默认值时才写属性。例子要像使用者会写的代码，属性越少越好。
- **例子不给组件化妆。** 演示行为时，内容用项目自己的组件（按钮 / 卡片）或纯文本，
  别手写 `.cell` / `.chip` 这类装饰层；`<style>` 只留给以样式为主题的演示
  （`part` / 自定义外观）—— 否则读者分不清是组件在起作用，还是示例的样式在起作用。
- **`doc-example` 是站点级组件**：在 `docs/layout.html` 注册一次，组件文档页不用为演示写任何 `<l-m>`。
  它的工具栏用 `mc-button`、普通例子切换器用 `mc-tabs` / `mc-tab`，这两批也由外壳统一注册
  （组件页的每个演示都用 `doc-example`）。
- ⚠️ **演示里用到的组件，只要不在站点级那批里，就要本页注册**：外壳注册的是
  `mc-code` / `mc-icon` / `mc-space` / `mc-collapse(-item)` / `mc-menu(-item)` /
  `mc-scroll-bar` / `mc-dropdown` / `mc-popover` / `mc-input` / `mc-button` / `mc-tabs` /
  `mc-tab` / `doc-example` 那一批，**不含 `mc-card` / `mc-breadcrumb`**。
  漏了的话 ofa 的 `*:not(:defined){display:none}` 会把没注册的标签连同文字一起藏掉 —— 不报错，
  只是演示区里那排按钮整个消失；而且同一个页面**两种表现**：从首页点进来正常，深链打开再刷新就
  空白（首页碰巧注册过 `mc-button`，深链 + 刷新时不保证渲染 —— message / popover 两页就这么炸过）。
  写法照 `packages/checkbox/page.html`：演示里用到 `mc-form` / `mc-form-item`（不在站点级那批），
  正文最前面就写它们的 `<l-m>`：

  ```html
  <l-m src="../form/form.html"></l-m>
  <l-m src="../form/form-item.html"></l-m>
  ```

  改这条约定时自己逐页对账：站点外壳 ∪ 本页 `<l-m>` ∪ 演示自己的 `load()` 必须盖住演示里用到的每个项目组件。

- **路径**：`<doc-example src="./demos/x.html">` 相对**文档页**解析；demo 文件内部的相对
  `src` / `href` / `import` 由 `docs/lib/demo-runtime.mjs` 按 demo 文件地址重写 —— 写例子时
  仍然按 demo 文件所在目录数（从 `demos/` 往上）。
- 改页面时逐页核对：每个 `.doc-demo` 恰好一条 `<doc-example>`、页面里没有
  `<l-m src="./demos/">` 与 `<demo-*>` 标签、`src` / `plain-src` 指向的文件存在；标题 / 说明
  留在页面里（右栏目录靠它）。

### `<doc-example>` 与「普通例子」

组件页的每个演示都用它；「基本用法」还各配一份 `basic-plain.html`（普通例子）。

```html
<section class="doc-demo">
  <doc-example src="./demos/basic.html" plain-src="./demos/basic-plain.html">
    <h3 slot="title">基本用法</h3>
    <p class="doc-hint" slot="hint">说明（可选）。</p>
  </doc-example>
</section>
```

- 标题 / 说明仍写在页面里，只是改成 slot；`doc-toc` 扫页面 shadow root 的规则不变。
- `src` 是 ofa 演示文件（如 `packages/button/demos/basic.html`，一个文件一个 `tag`）；`plain-src` 是
  配套的普通 HTML 完整页（如 `packages/button/demos/basic-plain.html`），只用于「普通例子」代码视图和
  iframe 预览。两个文件都要在页面里出现，`page-demos` 才不会报孤儿。普通版可缺省：没写 `plain-src`
  的演示只有 ofa.js 视图，切换器自动隐藏（现在每个组件的 `basic` 都有普通版；`button` 的
  `type` / `states` 也有）。
- 默认是 ofa.js 视图（左），普通例子（右）只切代码；只有点「运行」/「重新运行」才重编译或重跑
  当前视图。这两个按钮只在代码区展开时出现（收起时没有可运行的编辑），收起态只留复制与代码入口。
  普通例子的 CDN 地址在预览时映射到本地仓库，不依赖发布 tag。
- `src` / `plain-src` 都相对**页面文件**解析；`src` 会被 ofa 改写成绝对地址，`plain-src` 由组件按
  页面地址解析（button 页写 `plain-src="./demos/basic-plain.html"`）。
- `doc-example` 是站点级组件（`docs/layout.html` 注册），页面只写标签；它的工具栏依赖
  `mc-button`、普通例子切换器依赖 `mc-tabs` / `mc-tab`，也都由外壳注册。只有配了 `plain-src`
  的演示才会显示切换器。
- 站点组件表、运行时例外与 `src` 的解析规则见 [`docs/README.md`](../docs/README.md)。

## 三、参考区（属性 / 事件 / 插槽 / part）：写进 `api.md`，只放表

参考区**由 `<doc-spec src="./api.md">` 运行时渲染**，所以下面这些表和口径都写在
`packages/<slug>/api.md`（**纯渲染源**：开场白 + 白名单四节），页面里一个字都不抄。
四个参考节**只有表**，一句解释都不写。文档页只回答「叫什么、填什么、值是什么」；
「为什么这么设计」「底层用了什么机制」一律留在这里、组件 API 规范 与组件文件头。

⚠️ **节名收敛成四个**（2026-10）：`属性` / `事件` / `插槽` / `part`，顺序固定。
原来的 `方法` / `配置` / `插槽与 part` 三个节名去掉了 —— **配置就是属性**（同样 `名称 / 值 / 默认`）、
**方法就是事件**（同一张表，名称写调用式）、**插槽与 part 各占一节**。白名单落在
[`docs/lib/md-spec.mjs`](../docs/lib/md-spec.mjs)，节序与 `doc-drift.config.mjs` 的 `referenceOrder` 一致。

**表格五件事：**

| 规则                     | 说明                                                                                                                                                                                                  |
| ------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **第一栏一律叫 `名称`**  | 属性表 / 事件表 / 插槽表 / part 表都是 —— 表头别复述节标题（原来的「属性」栏、「事件」栏、「插槽」栏都只是在复述）                                                                                    |
| **一行一个名字**         | `插槽 header / footer` 要拆成两行，说明各自写全（哪一条线、什么时候占位），别写「同上」；`part` 同理                                                                                                  |
| **插槽与 part 各占一节** | 两节各写各的表、名字写**裸的**（`prefix`、`body`）—— `插槽 header` / `part="header"` 那种混合写法去掉了。只有一类就只写那一节，都没有就整节省略。`api-slot-part-title` 守卫盯着节名，也盯着名字别串节 |
| **配置表就是属性表**     | 命令式组件的配置项（`message()` 的 `DEFAULTS`）不单开一节：它就是 `属性` 表，同样 `名称 / 值 / 默认`，由配置里的 `imperatives.config` 拿源码 DEFAULTS 对账                                            |
| **值列写 TS 类型**       | `boolean` / `string` / `number` / 字面量联合 `'sm' \| 'md'`；**默认列仍是字面值**（守卫拿它跟代码逐字比）。联合的竖线按 GFM 转义；别再写「布尔 / 字符串 / 数字」。`api-value-ts` 守卫盯着这条         |

**事件表的「类型」写 TS 函数签名**：`(event: Event & { data: { name: string } }) => void`。
ofa 的 `emit(type, { data })` 交过来的是**原生 `Event` 加一个 `data`**（不是 `CustomEvent`，
实测 `ctor === Event`、`isCustomEvent === false`），没有 `data` 就写 `(event: Event) => void`；
字段类型按组件真实的 payload 写。

⚠️ **例外**：组件自己 `dispatchEvent(new CustomEvent(…))` 时（`before-open` 要 `cancelable`、
`scroll` 要重发，都绕不开原生派发），载荷在 **`event.detail`** 而不是 `data` ——
`mc-popover` 的三个事件就是这条路，类型写
`(event: CustomEvent<{ reason: string }>) => void`，别照抄 `data`。

**代码侧的同一事实写在组件定义顶部的 `emits` 里**（与 `attrs` 对称）：`data` / `detail` / `native` 选通道，数组写载荷键；
`withEmits(...)` 把它接成唯一派发口 `this.$emit('name', payload)`。`event-doc` 守卫拿这份声明跟这里的「类型」列对账：
`data` 通道写 `Event & { data: … }`，`detail` 写 `CustomEvent<…>`，无载荷写 `Event`。

**方法也写进这张表**：名称写调用式（`` `show()` `` / `` `loadingBar.start(config?)` ``），
类型写这个可调用的 TS 签名（`(reason?: 'api' \| 'trigger' \| 'dismiss') => void`）。
引擎的 `callRows` 认「名称里带调用语法」的行：它们按方法对账（名字要在源码里找得到），
其余按事件对账 —— 混在一张表里也不会被当成「代码里没有的事件」。

**落笔前问三句**（2026-09 全站清理用的就是这三刀）：

1. 这句是**机制**还是**事实**？机制 → 删（回这里或组件文件头）；
2. 是**事实**？→ 转成一张表（`data-current` 这类宿主钩子、`code` 的传值优先级，都这么处理）；
3. 已经在**演示里**（或演示正文里）说过？→ 直接删 —— 导语与演示正文撞车＝同一条信息两遍。

> ✅ 这三条现在有自动守卫了：`pnpm check:docs`（`tools/doc-drift/` + `tools/doc-drift.config.mjs`）
> 会对账 `api.md` 的**表头口径**、插槽 / part 的**节名**（`api-slot-part-title`）、
> **参考节里只有表**（`api-tables-only` —— 混进的解释句 / 代码块当场红）、
> **多标签组件的插槽 / part 要点名标签**（`api-multitag-slots-parts` —— 并集对账看不出漏）
> 与每张表跟组件代码（属性 / 事件 / 插槽 / part，含默认值），以及页面骨架与 `<doc-spec>` 接线。
> 它管不到的是**演示区**里的重复（导语与演示正文撞车）—— 那是判断，落笔时按上面的清单自查。

## 四、首页：方块场 + 两个入口（`docs/pages/home.html`）

首页是一整屏**方块场**：`<doc-block-field>` 铺满，四层方块各自跟随鼠标位移；
中间空出来的那块留给字标与两个入口。

- **首页只管「放在哪、中间留多大」**：视差、方块、颜色全在站点组件里
  （[`docs/components/block-field.html`](../docs/components/block-field.html)，属站点组件，
  见 [`docs/README.md`](../docs/README.md) §五）。这一页只剩 `.hero`（定位祖先 + 居中）
  与 `.hero-core`（字标 + 入口）。
- **中间要空**：方块场中心有一块椭圆禁区（组件的 `hole` 属性，默认 `0.3`），方块掷到里面就重掷；
  外层还有一圈边距，免得大块被视口切掉半截。方块数量、位移幅度分别是 `count` / `span`。
- **入口用项目自己的 `<mc-button>`**（本页 `<l-m>` 引入），点击改 hash 导航；「浏览组件」的
  落点是**算出来的**（`docs/site-map.js` 的 `firstPageOf`），不在页面里抄第二份路径。
